# NOPik: AI Agent Architecture in 1C

![Project Status](https://img.shields.io/badge/status-active-brightgreen) ![Language](https://img.shields.io/badge/language-1C%20%26%20Python-blue) ![License](https://img.shields.io/badge/license-MIT-green)

## 📖 Overview

**NOPik** — это архитектурный проект, демонстрирующий переход от монолитных систем к автономным ИИ-агентам на платформе 1С. Проект представляет собой полный цикл из 7 статей, разбирающих как теорию архитектуры, так и практическую реализацию.

Эта статья (часть 1) сосредоточена на теоретических основах и архитектурных решениях при построении ИИ-агента.

## 🎯 Основные темы проекта

### 1. **Архитектурный манифест: от кризиса к решению**
   - Критический анализ "наивного вайб-кодинга" в Enterprise-приложениях
   - Переход от жесткой привязки компонентов к гибким архитектурным паттернам
   - Адаптерный слой как альтернатива монолитным объектам

### 2. **Точка входа: адаптивная архитектура**
   - Отказ от жесткой привязки к объекту «Бот»
   - Использование адаптерного слоя для повышения гибкости
   - Слабая связанность компонентов системы

### 3. **Граф состояний и управление агентом**
   - **FSM (Finite State Machine)** — базовая теория
   - **HSM (Hierarchical State Machine)** — иерархические состояния
   - Практическое применение графов состояний для управления ИИ-агентом
   - Переходы между состояниями и обработка событий

### 4. **Инфраструктура разработки**
   - Переход от монолитной конфигурации к модульной архитектуре
   - **Git-based workflow** для версионирования 1С-конфигураций
   - **ibcmd** — инструмент для работы с 1С из командной строки
   - CI/CD интеграция для автоматизации тестирования и развертывания

### 5. **Практическая реализация на 1С**
   - Структура модуля бота в 1С
   - Обработка команд и взаимодействие с агентом
   - HTTP-сервисы для интеграции с внешними системами
   - Модули управления состояниями и логикой агента

### 6. **Живое тестирование**
   - 6 runtime-ошибок, которые не поймал компилятор 1С
   - Стратегии отладки и профилирования
   - Принципы unit-тестирования для модулей агента

### 7. **Расширенная реализация: Python & LangGraph**
   - Создание собственного оркестратора на Python
   - Использование **LangGraph** для управления сложными графами состояний
   - Интеграция Python-оркестратора с 1С-агентом
   - Кроссплатформенная архитектура

## 🛠️ Ключевые архитектурные паттерны

### Паттерн Адаптера
Позволяет системе взаимодействовать с различными типами агентов без изменения основного кода:

```
┌─────────────────┐
│  Внешний AGI    │
└────────┬────────┘
         │ HTTP/WebSocket
    ┌────▼─────────────┐
    │ Adapter Layer    │
    │ (in 1C)          │
    └────┬─────────────┘
         │
    ┌────▼──────────────────┐
    │ Core Agent Logic      │
    │ (FSM/HSM)            │
    └──────────────────────┘
```

### Граф состояний (FSM)
```
┌─────────────┐     request    ┌──────────────┐
│   IDLE      ├──────────────►│ PROCESSING   │
└──▲──────────┘               └────┬─────────┘
   │                               │
   │              error/timeout    │
   └───────────────────────────────┘
```

## 🚀 Использование

### Требования
- **1С:Предприятие** 8.3.20+ (поддержка HTTP-сервисов)
- **Python** 3.10+ (для оркестратора LangGraph)
- **Git** (для версионирования конфигурации)
- **ibcmd** (инструмент для работы с 1С)

### Установка конфигурации в 1С

1. Клонируйте репозиторий:
```bash
git clone https://github.com/NickScherbakov/nopik-articles-public.git
cd nopik-articles-public/articles/nopik-ai-agent-1c
```

2. Загрузите конфигурацию в 1С с помощью **1C Designer** (Конфигуратор):
   - Откройте 1С в режиме Конфигуратора
   - Загрузите конфигурацию из файла `Configuration.xml`

3. Опубликуйте изменения в информационной базе

### Использование Python-оркестратора

```bash
# Установите зависимости
pip install langgraph openai

# Запустите оркестратор
python orchestrator.py --config config.yaml
```
